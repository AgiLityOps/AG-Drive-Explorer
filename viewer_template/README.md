# AG Drive Track Explorer

A free-camera 3D explorer for every track in **AG Drive 1.4.5** (ZORG Entertainment, 2015), running in your browser.
This folder was generated by **AGDriveConverter** from your own copy of the game's IPA. All geometry, textures, skyboxes, fog
and lighting values were converted from that file on {{DATE}}.

## Start it

| System | What to do |
|---|---|
| Windows | Double-click **start.bat**. It uses Python 3 if you have it, otherwise a built-in PowerShell server. |
| macOS | Double-click **start.command**. The first time, you may need to right-click it, choose **Open**, then confirm. Needs Python 3 (`xcode-select --install` provides it). |
| Linux | Run `./start.sh` |

Your browser opens at `http://127.0.0.1:8642/` (or the next free port). Keep the console window open while you explore and close it to stop.
Opening `index.html` directly from disk won't work, because browsers block loading 3D files from `file://`.
Works in current Chrome, Edge, Firefox and Safari with WebGL2.

## Controls

| Input | Action |
|---|---|
| Click the 3D view | Capture the mouse for mouse-look (**Esc** releases it) |
| Drag | Look around without capturing the mouse |
| **W A S D** / arrow keys | Fly forward / left / back / right |
| **Space** or **E** | Fly up |
| **C** or **Q** | Fly down |
| **Shift** (hold) | Boost ×5 |
| Mouse wheel / *Speed* slider | Fly and ride speed, 10 to 30,000 units/s (tracks are about 5,000 to 15,000 units across) |
| **R** / *Back to start* | Return to the start line |
| **F** / *Ride racing line* | Ride the game's own racing line at the slider speed (**Shift** boosts). The camera banks and rolls with the track, and the mouse looks around |
| **V** | While riding, look straight ahead again |
| **N** / *Animations* | Turn the animations on or off |
| **G** / *Fog* | Toggle fog |
| **[** **]** or **PgUp** / **PgDn** | Previous / next track |
| **1–9, 0, -, =** | Jump straight to track 1–12 |
| **H** / *Help* | Show the controls |

*Brightness* scales the final image if a track looks too dark or too bright on your screen.
The bottom-right readout shows the camera position in viewer (Y-up) and game (Z-up) coordinates.
You can link straight to a track, for example `http://127.0.0.1:8642/#track_mirlon_03`.

## What changed in v2

* **Buildings and track surfaces look right now.** AG Drive stores its triangles with *clockwise* front faces, but glTF/three.js
  expects counter-clockwise. In v1 the viewer culled the real outside surfaces and showed the insides and undersides instead.
  That's why buildings looked hollow, misplaced or inside-out and the track looked like its underside. The stored normals agree
  with the clockwise winding on essentially every triangle, so v2 reverses the index order on conversion. the glowing sea grids,
  the light track surfaces and the city blocks now match the game's screenshots.
* **Textures are stored upright.** The game's `.tex` images are stored bottom-row-first (OpenGL style), so the v1 texture files were
  upside down when you opened them, for example in Blender. v2 flips every image and uses `v' = 1 - v`, so the files, the GLBs and the viewer
  all agree. Text on signs reads correctly, and the red road chevrons point in the race direction.
* **Smooth racing-line ride.** The `PathFinder` record in each `.aga` file is a full matrix every 10 units: forward and track-up vectors as well as position.
  The ride uses a closed centripetal Catmull-Rom spline sampled by arc length, so the speed stays constant. The track's up vector gives
  banking, loops and upside-down sections, and the camera is slerp-damped so it doesn't jitter.
* **Animations** (toggle with **N**):
  * Flying starships, the off-world ship, moving tower modules, spotlights and the intro track's ships, logos and UFO.
    These are the game's `d#(NNN)` objects, driven by record NNN of the track's `.aga` file at 30 fps (`assets/anim/*.bin`).
  * Ground traffic lanes (`1#traffic`, the game's scroll shader, including its separate underside strip) and flying traffic lanes (`2#traffic`) scroll.
  * Ad screens (`a#ads`) step through the ads in their atlas row.
  * The scroll and ad-cycle *speeds* are set by the engine at run time and aren't in the game data, so they're hand-picked.

## How it was made

* **Geometry**: each `.stg` (IonCore "STG1" static geometry) was parsed from scratch. Vertices are 32 bytes:
  position (3×f32), normal (4×i16, where w is baked sky visibility), UV (2×f32), and colour (4×u8: baked light RGB plus sun visibility).
  Ad screens use a 20-byte position+UV layout. Converted from the game's Z-up to glTF Y-up, and compressed with
  meshopt (gltfpack). The GLBs are in `assets/tracks/` and open in Blender or any glTF viewer. Textures are referenced from `assets/textures/` (WebP).
* **Textures**: the `.tex` files (LZ4-compressed PVRTC 4bpp/2bpp, plus two PVR v3 files) were decoded and saved as WebP.
  Texture alpha is the game's reflection/glow mask, not transparency, so materials are opaque except flying traffic and light flares.
* **Shading**: the viewer re-implements the game's GLSL from `shader_environment*.lua` (environment, track, emissive, metal, glass/grate,
  scrolling traffic, self-lit screens, water, additive flares). It uses each track's `diffuse_lighting_coefficients`, `glossy_lighting_coefficients`,
  sun colour and glossy reflection cubemap.
* **Sky**: the per-track skybox cubemap named in the track script, used as `scene.background`.
* **Fog**: each track's `fog` table (range, front/back colours, back curve). Fog strength follows the game's track shader, `min(0.99, sqrt(dist/range))`,
  and the colour blends from the back colour to the front colour toward the sun (direction from `sun_position_in_skybox`).
* **Start camera / racing line**: from the `PathFinder` animation track in each `.aga` file (position + orientation every 10 units).
* **Animations**: `.aga` records are 4×4 row-vector matrices. A `d#(NNN)` mesh is baked at frame 0 of record NNN, so its transform at time *t*
  is `inv(M0)·M(t)`. These are exported as reduced keyframes. The GLBs keep these objects as separate nodes named `anim_NNN_*`.

## Known differences from the game

* AG Drive bakes its lighting into vertex colours, so there is no real-time sun shading. That matches the game.
* Not animated: lens-flare blinking and lamp flares (the game spawns these at run time from `flare_types` / `light_types`; the positions aren't in the files),
  the intro camera fly-through paths, and racing ships (they're added by the game at run time).
* Scroll and ad-cycle speeds are approximations (see above).
* Some trackside objects that the game places at run time (`trackside_objects` tables) may be missing where they aren't baked into the `.stg`.
* `roadmat` is downscaled from 4096² to 2048² to keep the download smaller.
* The animated objects start at frame 0. The game probably randomises their start times (their records are named `randomize_*`).
